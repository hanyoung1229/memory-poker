- 화면 우측 하단 버전 표시는 **v1.4.0**으로 갱신됩니다.

# MEMORY POKER v1.2.0 — 친구들과 즐기는 멀티플레이 기억력 포커

별도의 패키지 설치 없이 **Node.js 20 이상**에서 실행하는 실시간 링크 초대형 게임입니다.
브라우저에서 1명이 방을 생성하면 `/r/ABC123` 형태의 링크가 생기며,
친구들이 그 링크로 참가해 각자의 휴대폰/PC에서 동시에 플레이합니다.

## 로컬 실행

```bash
npm start
```

- `http://localhost:3000` 방문 (Windows는 `start_windows.bat` 더블클릭으로도 시작할 수 있습니다.)
- 같은 Wi-Fi에서 테스트하려면 컴퓨터의 사설 IP 주소 및 방화벽 설정을 사용하세요 (예: `http://192.168.0.10:3000`). 외부 인터넷에서 접속하려면 배포해야 합니다.
- 테스트: `npm test`

## 게임 진행

1. 방 생성 → 초대 링크 복사 → 친구들 입장 → 전원 **준비 완료** → 방장 **게임 시작** (2~16명)
2. 52장 섞기. 맨 위 **16장**을 4×4로 뒷면 배치해 **5초 대기**
3. 해당 16장을 **20초 동안 공개**해서 외운 후 다시 뒤집음
4. 남은 덱의 맨 위 **3장을 공용 카드**로 공개
5. 모든 플레이어가 **10초 내에 16개 위치에서 2개 선택**. 카드는 최종 선택 시점까지 뒷면이고, 각자의 선택 내용은 결과 공개 전까지 비공개
6. **공용 3장 + 각자 선택한 2장**으로 정확히 5장의 표준 포커 족보 대결
7. 우승/공동 우승 발표 → **누적 승수 갱신** → 방장 **바로 다음 판 시작** 버튼으로 로비 없이 재경기 (또는 **대기실로 돌아가기**)

### v1.2.0 업데이트 — 화면 배치 및 버전 확인

- 4×4 기억 카드 사이 간격을 기존 대비 **1.3배**로 조정 (PC 12→15.6px, 태블릿 10→13px, 모바일 8→10.4px).
- 승부 결과창을 4×4 기억 카드 **바로 위**로 이동했습니다.
- 방장 화면의 `↻ 로비 없이 바로 다음 판 시작` 버튼을 **결과창 맨 위**에 배치했습니다. 결과가 확정된 **result 단계에서만 방장에게 보입니다**. 다른 참가자는 방장을 기다린다는 안내가 보입니다.
- 화면 **우측 하단**에 `MEMORY POKER · v1.2.0`을 항상 표시합니다. v1.2.0이 보이지 않으면 새 버전이 아직 배포되지 않았거나 브라우저에 이전 화면이 남은 것입니다.
- 정적 CSS와 JavaScript 주소에 `?v=1.2.0`을 넣어 업데이트 때 캐시가 갱신되기 쉽게 했습니다.

### 중요: GitHub에 업데이트 올리는 방법

1. 압축파일을 풀면 `memory-poker` 폴더가 있습니다.
2. GitHub 저장소 `hanyoung1229/memory-poker`의 **최상위(root)** 업로드 화면에서 압축 해제된 **`memory-poker` 폴더 전체**를 업로드하세요. 기존 폴더 내부에서 다시 `memory-poker` 폴더를 업로드하면 `memory-poker/memory-poker` 경로로 중복되어 적용되지 않습니다.
3. 기존과 겹치는 파일들이 변경된 것을 확인하고 `Commit changes`를 누릅니다. 커밋 수가 늘었는지 확인하세요.
4. Render에서 새로운 배포가 자동으로 시작되지 않으면 `Manual Deploy → Deploy latest commit`을 선택합니다. 기존 배포 기록 1개만 남아 있다면 업데이트가 적용되지 않은 상태입니다.
5. 배포가 `Live`가 되면 게임을 새로고침하고 오른쪽 아래 **v1.2.0** 표시를 확인하세요. 브라우저 캐시가 남았다면 `Ctrl+Shift+R`로 강력 새로고침하세요.
6. 새 배포 때 메모리에 있던 기존 게임 방은 초기화됩니다. 새 방을 만들어 테스트해 주세요.

### 새 기능: 승수 기록 및 즉시 재시작 (v1.1)

- 참가자 목록을 누적 승리 횟수가 높은 순서대로 표시하고, 결과 화면에도 각자의 **누적 N승 / 참여 N판**을 보여줍니다.
- **공동 우승한 플레이어는 각자 1승**이 올라갑니다. 같은 라운드가 중복 집계되지 않도록 서버가 결과를 한 번만 확정합니다.
- 결과 발표 뒤 **방장만** `↻ 바로 다음 판 시작`을 누를 수 있습니다. 모든 플레이어에게 즉시 새로 섞은 카드가 배치되며 기존 **5초 대기 → 20초 암기 → 10초 선택**이 이어집니다.
- 기존 방 코드, 초대 링크, 참가자, 누적 승수는 그대로 유지됩니다. 이전 판에 관전으로 들어온 참가자도 다음 판에 자동 참여합니다.
- 준비 여부를 다시 확인하고 싶은 경우 방장이 `대기실로 돌아가기`를 누르면 기존처럼 전원 준비 후 시작할 수 있습니다. **대기실로 가도 승리는 유지됩니다.**
- 승수와 참여 판수는 현재 방에서만 유지되는 **서버 메모리 정보**입니다. 방 삭제·퇴장 또는 Render 서버 재시작/재배포 후에는 복원되지 않습니다. 새 버전을 처음 배포할 때 현재 방 정보는 초기화됩니다.

### 확정한 운영 규칙

- 서로 다른 참가자가 **같은 위치**를 선택할 수 있습니다. (각자의 선택권이 독립적)
- 한 플레이어는 **서로 다른 두 위치**를 선택합니다. 10초 동안 재선택 가능
- 선택을 안 했거나 1장만 선택한 참가자는 남은 자리를 **자동 무작위 선택**합니다.
- 게임 도중 입장한 사람은 해당 판 **관전**, 다음 판부터 참가 가능합니다.
- **금전 베팅 없음**, 5장 포커(스트레이트 플러시/포카드/풀하우스/플러시/스트레이트/트리플/투페어/원페어/하이카드), 동점이면 공동 우승. A-2-3-4-5는 5 하이 스트레이트, 무늬 우열 없음.
- 16장과 공용 3장은 같은 52장 덱에서 중복 없이 뽑습니다.

## 인터넷 링크로 배포 (Render 예시)

서버가 필요한 게임이므로 단순 HTML 파일을 공유하거나 GitHub Pages에 올리는 것으로는 다중 기기 실시간 플레이가 불가능합니다.

1. 소스 파일 전체를 GitHub 비공개 또는 공개 저장소에 올립니다.
2. Render의 **New → Web Service**에서 저장소를 연결합니다.
3. Runtime: Node, Build Command: `npm install`, Start Command: `npm start` (또는 리포지토리의 `render.yaml` 사용).
4. 생성된 `https://서비스주소.onrender.com` 등 배포 URL을 친구들과 공유합니다.
5. 화면에서 **새 게임 방 만들기**를 누른 뒤 **초대 링크 복사**를 사용합니다.

> Render 무료 Web Service는 유휴 상태에서 15분 후 잠들고 재시작 시 메모리에 있던 방이 사라질 수 있습니다. 실제 플레이 중에는 브라우저가 열려 있을 때 3분마다 경량 접속 확인을 수행합니다. 요금/휴면 정책은 실제 배포 시 확인하세요.

## 파일 구조

- `server.js`: 의존성 없는 Node HTTP + SSE 실시간 전송 서버, 닉네임/초대 코드/방장/라운드 관리
- `lib/game.js`: 서버에서 독점적으로 처리하는 타이머·배포·선택·승부 흐름
- `lib/poker.js`: 공정한 카드 섞기(암호학적 난수) 및 표준 포커 족보 비교
- `public/`: 모바일 및 PC를 위한 한국어 UI
- `test/`: 카드/족보/타이머 등 자동 테스트

## 주의 / 확장

- 현재 방과 참여자 정보는 **서버 메모리**에만 저장됩니다. 재시작/재배포 때 사라집니다. 장기 운영 시 Redis 같은 외부 저장소가 필요합니다.
- 서버를 **복수 인스턴스**로 띄우면 방 정보가 공유되지 않습니다. 단일 인스턴스로 배포해야 합니다.
- 게임은 SSE(EventSource)를 통한 푸시 동기화 방식입니다. 브라우저마다 타이머는 서버 기준으로 표시하고, 카드 내용/선택 결과는 서버가 관리합니다.
- 6시간 동안 변경이 없는 방은 서버에서 자동으로 정리합니다.
- 링크를 가진 누구나 입장할 수 있고, 접속자 닉네임은 공개됩니다. 친구들 간 소규모 게임용입니다. 공개 서비스 운영 시 비밀번호, 속도 제한, 영구 저장소, 모니터링 추가를 권장합니다.
